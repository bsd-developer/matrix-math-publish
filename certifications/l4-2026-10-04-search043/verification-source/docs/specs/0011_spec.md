# 0011 — Outward dyadic rounding as the registered exact arithmetic

**Status:** Normative; amends the §7.2/§7.3 directed-arithmetic contract of `0001_spec.md`, discharges the amendment obligation `0007_spec.md` §5.7 and ADR 0011 name, and ratifies ADR 0011 (status moves to accepted)  
**Document version:** 1.0.0  
**Date:** 2026-08-23  
**Audience:** an implementer with no prior repository context who has read ADR 0011  
**Target:** `crates/mm-rat/`, both exact evaluators in `crates/mm-exact/`, and the executable directed bounds of `lean/MatrixMath/Numeric/`

---

## 1. The rule

Every directed enclosure, at the point it is **produced**, is snapped outward
onto the shared dyadic grid `2^-B` with

```text
B = log_precision_bits + 32
```

— the lower endpoint by `floor_dyadic`, the upper by `ceil_dyadic`. This is
unconditional: the former `mm-rat/dyadic-rounding` Cargo feature is deleted
rather than defaulted on, so no build configuration can reintroduce the
unrounded arithmetic. Production points, exhaustively: `round_outward` in
`crates/mm-rat/src/log2.rs` (the single Rust call site), and the
`floorDyadic`/`ceilDyadic` snap inside `log2Lower`/`log2Upper` in
`lean/MatrixMath/Numeric/Log2Bounds.lean`. Entropy terms inherit the grid by
multiplication with dyadic certificate rationals and are not snapped again.

## 2. The load-bearing premise, stated as an invariant

The grid survives multiplication because **every certificate rational is
dyadic** (`0007_spec.md` §7.5 step 4; `python/mm_opt/rationalize.py`). A future
change admitting a non-dyadic certificate rational silently voids the grid
argument and the measured speedup with it; if that ever becomes possible, the
rounding MUST move to after the scale in `term_enclosure_with`, and this
document MUST be amended first. Until then, any producer path that would emit a
non-dyadic rational is a defect against this section.

## 3. Soundness and the precision budget

`floor(x) ≤ x` and `ceil(x) ≥ x`, so a rounded lower bound is a lower bound
and a rounded upper bound is an upper bound, and every §7.2 propagation rule
composes unchanged. Every rounding moves the A21 verdict **toward rejection**:
rounding can never accept a certificate the unrounded arithmetic rejects. In
Lean this is exactly two lemmas (`floorDyadic_le`, `le_ceilDyadic`) composed
once into each of `log2Lower_le` and `le_log2Upper`; no other proof changes.

The error budget is ADR 0011's: one rounding per evaluation adds under
`2^-(precision+32)`, the composed width stays under `2^-precision`, so
`0004_spec.md` P1, P4, and P5 hold **unamended**, and `log_evaluations` is
unchanged because a rounding is not an evaluation. At `B = precision + 32` the
accumulated `ℓ*=4` effect on `Ω` is four orders below the `2^-64` reporting
grid; the committed fixtures' certified ceilings are bit-identical, and the
gates below re-verify rather than assume that.

## 4. One behavior, two checkers

Both Rust exact evaluators (general and symmetric) perform the identical
snapped arithmetic — the §5.7 identity `crates/mm-exact/tests/symmetric_masses.rs`
asserts as exact rational equality, now in the default build. The Lean
executable bounds snap on the same grid, in the same directions, at the same
production points. Rust and Lean intentionally compute their series by
different constructions (`artanh × enclosed 1/ln2` versus a series quotient),
so their contract is and remains **verdict parity on the corpus plus the
soundness ordering**, not bitwise equality of intermediate rationals; the
exit-6 differential is the gate that holds it.

## 5. Gates

All of them, before this document's implementation commit is complete:

1. `mm-rat`'s on-grid endpoint test runs unconditionally (the off-grid arm is
   deleted with the feature).
2. The full test tiers pass on the default build — which now includes the
   formerly feature-gated §5.7 identity battery via `just test-slow`; the
   `test-rounding` recipe is deleted as redundant.
3. Corpus re-verification: every committed certificate and test vector is
   re-checked under the rounded chain with unchanged verdicts; committed
   certificate bytes are never regenerated (`0004_spec.md` precedent);
   development fixtures whose recorded digests move are regenerated by
   `just fixtures` in the same change, or the change does not land.
4. The Lean assurance audit passes with the axiom budget unchanged —
   `AX1_combination_loss` plus certificate-specific `native_decide` axioms and
   nothing new.
5. The ADR 0011 revision records the post-cutover measurements, including the
   `ℓ*=4` producer/checker figures that motivated legality.

## 6. Non-goals

- No search-side change: the float optimizer never executes this arithmetic.
- No producer-accounting change: `charge_elided_evaluations` and the §4.1
  count contract are untouched.
- No claim about `ℓ*=4` search quality: this document makes `ℓ*=4`
  certification tractable; finding a point worth certifying there remains the
  open basin problem.
