## 0. Implementation analysis and results

This specification was amended after Stages A–E and the generic proof bridge
were implemented.  The implementation establishes the following results.

1. `SymCert.expand` is total and level-generic.  Its root and recursive child
   arrays use the same region-major, shape/split-minor order as the general
   instance.  Compact `α` lookup is fail-closed outside the derived domain.
2. `SymCert.expandBlocks` now emits the root block six times and every interior
   level from `3` through `levels` **inclusive**, in the exact order consumed by
   `blockOffset`: level ascending, general `posNodesAt` order, then region.
   The earlier top-level omission was a real implementation defect and is
   removed, not retained as a compatibility case.
3. The compact checker mirrors the general checker conjunct for conjunct while
   evaluating class-constant quantities once.  Class mass uses the six
   reachable region slots explicitly; it does not accidentally include an
   overlong malformed payload's unreachable entries.
4. All five generic bridge obligations are proved with no `sorry`, `admit`, or
   new axiom: class `β`, class-region `β`, class mass aggregation,
   well-formedness transport, and compact-check acceptance implying general
   expansion acceptance.
5. `#print axioms` on `SymCert.check_implies_expand` lists only `propext`,
   `Classical.choice`, and `Quot.sound`.  The downstream omega and byte/digest
   theorems add only the existing `AX1_combination_loss`.  There is no
   symmetry axiom and no per-certificate bridge axiom.
6. The real compact symmetric level-three artifact with digest prefix
   `edad54aa` is accepted by the compact Lean checker.  Its exact `m_total`
   agrees with the independent Rust symmetric checker to the last bit.  The
   generated theorem uses the permitted CN native-evaluation mechanism and the
   CLI refuses publication if `sorryAx` appears.

These results close the implementation proof obligation.  They do **not** yet
claim a terminal level-four CN run: the recorded real level-four compact
artifact and full completion battery in §7 remain the capability gate.

## 1. Scope and semantic contract

The general Lean development already states `CombinationLossFeasible` and
`AX1_combination_loss` for arbitrary supported levels.  A general level-four
certificate therefore needs no new soundness mathematics, but its materialized
tree is impractical: the recorded instance has 1,552,339 nodes and about 416 MB
of certificate data.  The symmetric encoding stores one payload per
level-shape class and one maximum-entropy block per block-carrying class.

The compact object's meaning is exactly its expansion:

```text
Meaning(c : SymCert) := Meaning(c.expand : TrackACert)
```

The compact checker is an efficient evaluator of that meaning.  It is not a
new optimization objective, a relaxed checker, or evidence about an untied
point.  Nothing in this specification changes Appendix A, the general byte
encoding, the directed log bounds, `AX1`, or the CK/CN trust policy.

## 2. Canonical compact object and byte format

### 2.1 In-memory model

`SymCert` contains:

- `q`, `levels`, the rational omega claim, and log precision;
- one branching root payload;
- `groups`, a positional array of `GroupPayload` values;
- `blocks`, a positional array of general `Block` values.

A `GroupPayload` is exactly one of:

- `branching weights alpha` for a positive class at level at least three;
- `zeroShape beta` for a zero-shape class; or
- `levelTwo mu` for a positive level-two class.

The bytes carry no node rows, group keys, class multiplicities, rational-width
field, or multiplicity field.  All domains, variants, keys, counts, and
multiplicities are derived from `(levels, shape)`.

### 2.2 Group and block order

`symGroupList levels` is ordered by level **decreasing** from `levels` to two,
then by `shapeList` lexicographic order.  The group array contains payloads in
that order; a group does not repeat its key in the bytes.

`symBlockKeyList levels` deliberately uses the other level direction:

1. the root key `none`;
2. for each level from three through `levels` **ascending**;
3. each positive shape in lexicographic order.

The opposite directions are not interchangeable.  Groups follow the first
class encounters in preorder; blocks follow the general A20/block-offset
evaluation order.

### 2.3 JSON byte spine

The symmetric encoding uses the repository's canonical JSON certificate
spine.  Keys are consumed literally and positionally in this order:

```text
claim { l_star, omega, q }
kind = "omega"
payload {
  encoding = "symmetric"
  groups = [ derived payload sequence ]
  log_precision_bits
  max_entropy_blocks = [ derived block sequence ]
  root { alpha, region_weights }
}
schema
source_hashes { S1, S2 }
spec_version
```

Rationals use the canonical numeric grammar inherited from the general
certificate.  Array lengths are not prefixed by an extra rational-width or
multiplicity word: `readRatArray` receives the exact expected length from the
instance-derived domain.

## 3. Decoder and checker responsibilities

### 3.1 `Schema.decodeSymOmega`

`decodeSymOmega : Limits → ByteArray → Except DecodeError SymCert` is total and
resource-bounded.  It:

- rejects bytes beyond `Limits.maxBytes` before parsing;
- accepts only supported levels two through four, positive `q`, nonnegative
  omega, and precision in `[32,4096]`;
- matches the canonical key/string spine, schema version, spec version, and
  locked source hashes exactly;
- reads group payloads positionally against `symGroupList`, selecting each
  payload variant and rational-array length from the derived class;
- reads exactly `symBlockKeyList levels |>.length` blocks;
- reads root `alpha` over `shapeList levels` and exactly six region weights;
- rejects trailing bytes.

The decoder establishes canonical syntax and instance-derived layout.  It does
not prove simplex, probability, support, or maximum-entropy side conditions;
those belong to `SymCert.check`.  Because keys and counts are not present as
free byte fields, there is no separate decoder check for a claimed class key or
multiplicity.

### 3.2 `SymCert.symWf` and `SymCert.check`

`symWf` checks the root and every derived class:

- six nonnegative region weights summing to one;
- `alpha` length, nonnegativity, and unit sum over the derived shape/split
  domain;
- the payload variant required by positivity and level;
- zero-shape `β` length, probability, and support membership;
- level-two `mu ∈ [0,1/2]`;
- exact group and block array counts.

`SymCert.check` then evaluates the compact counterparts of the general
checker:

- root lower bound and side conditions;
- every interior level and positive class;
- positive level-two and zero-shape leaf contributions;
- class-aggregated `M_total`;
- the directed requirement upper bound and final A21 inequality.

The checker uses exact rationals and the existing outward-directed
`hLower`, `log2Lower`, `log2Upper`, penalty, and conditional-entropy routines.
It introduces no floating-point or approximate trusted computation.

## 4. Expansion definition

### 4.1 Node expansion

`SymCert.expandInstance` constructs root children in this order:

```text
for region in 0..5:
  for shape in shapeList(levels):
    mkNode(levels, region, shape, rootAlphaOf(shape))
```

For a positive class `(ℓ,s)` with `ℓ ≥ 3`, `mkNode` constructs children in the
corresponding order over `splitList ℓ s`.  Positive level-two and zero-shape
classes become their general leaf constructors.  The child order is part of
the meaning because complement pairing is reversal of the canonical split
list.

`GroupPayload.alphaOf domain s` returns the positional entry only when `s` is
in `domain`; otherwise it returns zero.  This matches the general checker's
total, fail-closed lookup semantics on malformed values.

### 4.2 Block expansion

`SymCert.expandBlocks` is:

```text
replicate 6 (blockAt none)
++ for ℓ in [3 .. levels] ascending:
     for entry in expandInstance.posNodesAt ℓ:
       replicate 6 (blockAt (some (ℓ, entry.node.shape)))
```

The inclusive top level is mandatory.  The addressing theorem proves that for
valid `j` and region `r`:

```text
expandBlocks[blockOffset(expandInstance, ℓ) + 6*j + r]
  = blockAt(some (ℓ, posNodesAt(ℓ)[j].shape)).
```

`SymCert.expand` packages the expanded instance and blocks with the unchanged
omega and precision into `TrackACert`.

## 5. Generic proof architecture

The bridge is a theorem over arbitrary `SymCert` values, not a computation on
the published artifact.  Its helper structure is the landed structure below.

### 5.1 Enumeration, child order, and lookup

- `splitList_nodup`, `shapeList_nodup`, and membership lemmas connect derived
  enumerations to levels.
- `map_alphaOf_eq` connects positional compact arrays to domain lookup.
- `classKids_filter_region` and `rootKids_filter_region` recover the exact
  canonical child list for one region.
- `alphaAt_classKids` proves agreement with the general shape-keyed lookup.
- the complement/reversal and zip/map lemmas prove that compact split pairing
  is the general `betaRegion` pairing.

### 5.2 The five bridge obligations

1. `classBeta_eq`: strong induction on the level proves that every expanded
   node's `betaOf` equals its class `β`, independently of parental region and
   alpha.
2. `classRegionBeta_eq`: filtering class children to a region and reversing
   the canonical split list gives the compact class-region mixture.
3. `classMass_eq`: exact-level preorder lemmas, one-level mass conservation,
   six-region factorization, positive-parent grouping, and downward induction
   prove that the sum of expanded node masses in `(ℓ,s)` equals `classMass ℓ s`.
4. `wf_expand`: `wfNode_mk` transports every class payload recursively, while
   root filter/order and alpha-sum lemmas establish `wfInstance`.
5. `check_implies_expand`: root, interior, level-two, leaf, and `M_total`
   lower/Ok transports are composed.  Interior three-tuples are factored by
   node mass, regrouped by class mass before `min3q`, and addressed through the
   proved block-offset equality.

The resulting theorem is:

```text
SymCert.check_implies_expand :
  c.check = true → TrackACert.check c.expand = true
```

Acceptance implication is the required contract.  Rejection equality is not
claimed: the compact side conditions are class-aggregated and need only imply
the corresponding per-node general side conditions under compact
well-formedness.

### 5.3 Soundness composition

The generic omega theorem is the existing general theorem applied to the
expansion:

```text
SymCert.omega_le_of_check h :=
  TrackACert.omega_le_of_check (SymCert.check_implies_expand h)
```

The schema layer proves decode/check, claim, and digest-bound variants:

- `checkSymOmegaBytes_omega_le`;
- `omega_le_of_acceptsSymOmega`;
- `omega_le_of_acceptsSymOmegaDigest`.

No certificate-specific comparison between compact and expanded evaluation is
trusted by these theorems.

## 6. Trust, CLI, and publication

- The Lean compact checker and Rust symmetric checker remain independent
  implementations.
- The generic bridge has no project axiom.  The final mathematical result uses
  only the existing `AX1_combination_loss` in addition to Lean's standard
  foundational axioms.
- A generated CN module embeds the published compact bytes, exact rational
  claim, and SHA-256 digest, and proves one closed
  `acceptsSymOmegaDigest` Boolean with the permitted native-evaluation
  mechanism.
- `mm-cli prove` selects symmetric generation from the decoded encoding.  It
  checks derived group/block counts, emits the compact theorem chain, refuses
  CK for opaque core-rational evaluation, and refuses publication if the
  generated result carries `sorryAx`.
- `mm-cli verify` and the Rust symmetric path are diagnostics and conformance
  evidence; they are not imported into Lean soundness.

Compact checking never materializes the 1,552,339-node level-four expansion at
runtime.  Expansion exists in definitions and generic proofs only.

## 7. Acceptance gates

### 7.1 Completed implementation gates

- The decoder accepts the real compact level-three artifact.
- Compact Lean and independent Rust agree exactly on its reported total.
- `expandBlocks` has a general inclusive-level membership theorem and a proved
  block-offset addressing theorem.
- Focused Lean builds of `SymOmega`, `SymCheck`, `Schema.SymOmega`, and
  `SymBridge` pass.
- `#print axioms` is clean of `sorryAx` for the bridge, omega theorem, and
  digest-bound schema theorem; only the permitted `AX1` appears downstream.
- The symmetric CLI generator's focused Rust formatting and Clippy gates pass.

### 7.2 Required before a level-four capability claim

1. Run the repository completion battery: `just doctor`, `just build`,
   `just lint`, and `just test`.
2. Run the assurance audit with the compact theorem registrations and verify
   the exact axiom allowlists mechanically.
3. Run `just source-digest` twice after the final normative edits and require
   identical digests.
4. Decode and check the recorded real compact level-four artifact, generate
   its CN module, and run that module to a terminal record.
5. Preserve the compact bytes, claim, digest, tool/source closure, command, and
   terminal output.  A resource-limit termination is a censored measurement,
   not a successful capability claim.

Differential fixtures should continue to compare compact Lean, symmetric Rust,
and general expansion wherever materializing the expansion is practical.  Such
fixtures are regression evidence; they do not replace the generic theorem.

## 8. Non-goals

- No partially asymmetric or shared-DAG certificate.
- No change to the general encoding or Appendix A semantics.
- No backward reader for superseded development-only compact formats.
- No float, MPFR, or approximate arithmetic in the trusted path.
- No runtime expansion as a precondition of compact checking.
- No per-certificate bridge axiom or sampled equality in place of the proof.
- No claim that the level-four CN evaluation is fast until the terminal gate is
  measured.
- No search-side objective/checker change.  The separate level-four R1--R4
  search program is untrusted and outside this certificate specification.
